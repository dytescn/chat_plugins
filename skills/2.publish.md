# 发布前检查

本仓库的两个包都是 `type: sys`，发布产物与版本由各自的 `dytes.json` 决定。
发布流程由 dytes 统一管理；本地只做构建、清单校验和 dry-run，不手工直传生产 S3。

## 1. 版本与 uuid

- `Cargo.toml` 与 `dytes.json` 的版本保持一致；
- `dytes.json` 的 `uuid` 必须稳定，不能随版本变化；
- 禁止把 API Key、token 或本地配置写入 `dytes.json` / README。

## 2. 清单检查

```bash
cd deepseek
cat dytes.json

cd ../siliconflow_t2t
cat dytes.json
```

逐项确认：

- [ ] `name`、`uuid`、`version`、`type` 存在且正确；
- [ ] `exports` / `platform-exports` 的源路径在 `cargo build --release` 后确实存在；
- [ ] 导出目标文件名与 cyctron 端点一致；
- [ ] `init` 指向的 `setup.ts` 存在；
- [ ] `dependencies-sys` 只声明实际使用的库。

## 3. 构建

```bash
cd deepseek && cargo build --release
cd ../siliconflow_t2t && cargo build --release
```

## 4. 联调验收

发布前至少完成一次 `plugintest/` 冒烟：

- cyctron 能加载插件；
- `post_chat` 能读取 `info.db` 配置；
- 使用真实 Key 请求一次成功；
- 错误 Key / 空 prompt 能返回预期错误码。

## 5. 发布

- 由 dytes 打包/发布，不手工复制到生产目录；
- 发布后核对包的版本、uuid 与导出文件；
- 记录发布版本和验证结果到 `todo/`。

## 6. 当前待统一的差异

- `deepseek/dytes.json` 导出名为 `deepseek.dll`，TS 客户端端点为 `/libdeepseek`；
  发布前确认 cyctron 实际加载名，避免端点找不到库。
- `siliconflow_t2t` 目前只有 Windows `platform-exports`。
