# 发布前检查

本仓库剩余包以 `do_test_chat` 等 `design_plugins` 为主；供应商适配包
（`deepseek` / `siliconflow_t2t`）已迁移到独立系统库
[`dytescn/cloud_lib`](https://github.com/dytescn/cloud_lib)，发布流程也在该仓库。
发布流程由 dytes 统一管理；本地只做构建、清单校验和 dry-run，不手工直传生产 S3。

## 1. 版本与 uuid

- `Cargo.toml` 与 `dytes.json` 的版本保持一致；
- `dytes.json` 的 `uuid` 必须稳定，不能随版本变化；
- 禁止把 API Key、token 或本地配置写入 `dytes.json` / README。

## 2. 清单检查

```bash
cd do_test_chat
cat dytes.json
```

逐项确认：

- [ ] `name`、`uuid`、`version`、`type` 存在且正确；
- [ ] `exports` / `platform-exports` 的源路径在 `cargo build --release` 后确实存在；
- [ ] 导出目标文件名与 cyctron 端点一致；
- [ ] `init` 指向的 `setup.json` 存在；
- [ ] `dependencies-sys` 只声明实际使用的库。

## 3. 构建

```bash
cd do_test_chat && cargo build --release
```

## 4. 联调验收

发布前至少完成一次 `plugintest/` 冒烟：

- cyctron 能加载插件；
- `post_chat` 能读取 `info.db` 配置；
- 错误输入能返回预期错误码。

供应商（DeepSeek / SiliconFlow）联调在 `cloud_lib` 仓库完成。

## 5. 发布

- 由 dytes 打包/发布，不手工复制到生产目录；
- 发布后核对包的版本、uuid 与导出文件；
- 记录发布版本和验证结果到 `todo/`。
