# 使用 plugintest 做插件测试

`plugintest/` 是本地 cyctron 运行目录，用于加载 `cloud` 等系统库并调用
`post_chat`。运行产物不进入 git。

## 1. 目录

```text
plugintest/
├── cyctron.exe
├── libary/
│   ├── database.dll
│   ├── info_lib.dll
│   └── libcloud.dll
├── database/
│   ├── info.db
│   └── router.db
├── web/                 # cyctron 页面（可选）
└── dytes.json           # 测试应用清单（可选）
```

## 2. 构建并部署 cloud

```bash
cd ../../../sys/cloud
cargo build --release
cp target/release/cloud.dll ../design_plugins/chat_plugins/plugintest/libary/libcloud.dll
```

如果 `dytes.json` 的导出名与上面不同，以清单为准；cyctron 端点为 `/libcloud`。

## 3. 准备配置

`cloud` 的 `setup.json` 通过 `info_lib` 写 `info.db.setting`。启动 cyctron 后执行：

```bash
# 在 plugintest 目录，按 dytes 的 init 机制执行
dytes install sys cloud
```

也可以直接用 `info_lib` 的 `info_post` / `info_update` 写入
`deepseek_app_key`、`silicon_app_key` 等配置。不要把真实 Key 写进脚本或仓库。

## 4. 启动 cyctron

```bash
cd plugintest
./cyctron.exe start
```

cyctron 默认监听 `127.0.0.1:44944`。

## 5. 冒烟调用

```bash
curl -s -X POST http://127.0.0.1:44944/libcloud \
  -H "Content-Type: application/libary" \
  -H "FFI-Symbol: chat" \
  -d '{"supplier":"deepseek","prompt":"你好","max_tokens":64}'
```

```bash
curl -s -X POST http://127.0.0.1:44944/libcloud \
  -H "Content-Type: application/libary" \
  -H "FFI-Symbol: chat" \
  -d '{"supplier":"siliconflow_t2t","prompt":"你好","max_tokens":64}'
```

预期：

```json
{"code":0,"data":{"content":"..."},"msg":"success"}
```

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 404 / 找不到库 | 检查 `libary/` 文件名与 `dytes.json` 导出名、cyctron 端点 |
| `500101` | 检查 Key、base_url、网络和 `info.db` 配置 |
| `400004` | `supplier` 不是 `deepseek` / `siliconflow_t2t` |
| 修改 DLL 后行为不变 | 停止 cyctron，覆盖 DLL，再启动 |
| `Address already in use` | 已有 cyctron 进程，先停止旧实例 |
| `info.db` 无配置 | 执行 `setup.json` 或手工写入 setting |

## 7. 清理

`plugintest/libary/`、`plugintest/database/`、日志和 DLL 都不入库；换机器时重新部署即可。
