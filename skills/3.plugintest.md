# 直接测试 FFI 接口

本地不再通过 cyctron 暴露 HTTP 端点测试插件。测试时直接用
`scripts/ffi_call.py` 加载动态库并调用导出的 `post_chat`，与宿主的调用方式一致：

```text
ctypes.CDLL -> getattr("post_chat") -> post_chat(json_in, json_out) -> c_int
```

## 1. 前置

| 组件 | 要求 |
| --- | --- |
| 操作系统 | Windows / Linux / macOS |
| Rust | stable（Windows 用 MSVC 工具链） |
| Python | 3.8+，位数与动态库一致（Windows 必须同为 x64） |

不需要启动 cyctron，也不需要 `127.0.0.1:44944` 端点。

## 2. 构建并直接调用

```bash
cd think_base_call
cargo build --release
python ../scripts/ffi_call.py \
  --lib target/release/think_base_call.dll \
  --input '{"input":"你好"}'
```

Linux / macOS 把 `--lib` 换成 `libthink_base_call.so` / `libthink_base_call.dylib`。

预期输出：

```json
{
  "return": 0,
  "response": "{\"code\":0,\"data\":{\"outputs\":[\"测试你好\"],\"prompts\":[\"问候\"]},\"msg\":\"success\"}"
}
```

脚本规则：

- 入参是 UTF-8 JSON，自动补 NUL；
- 输出缓冲区固定 64 KiB，与插件约定一致；
- `return` 为 FFI 返回值，`response` 为原始 JSON 字符串；
- 返回码 `0` 且响应 `code` 为 `0` / `200` 时退出码为 `0`，否则为 `1`。

## 3. 指定符号与工作目录

`--symbol` 默认 `post_chat`。`cloud_lib` 等依赖 `info.db` 的库需要从测试根目录调用：

```bash
python scripts/ffi_call.py \
  --lib plugintest/libary/cloud_lib.dll \
  --cwd plugintest \
  --symbol post_chat \
  --input '{"supplier":"deepseek","prompt":"你好","max_tokens":64}'
```

## 4. 常用参数

| 参数 | 说明 |
| --- | --- |
| `--lib` | 动态库路径，必填 |
| `--symbol` | 导出符号，默认 `post_chat` |
| `--input` | 请求 JSON，默认 `{}` |
| `--cwd` | 调用前切换的工作目录 |
| `--json` | 只输出响应 JSON，便于管道处理 |

## 5. 冒烟用例

`think_base_call`：

| 输入 | 期望 |
| --- | --- |
| `{"input":"你好"}` | `prompts:["问候"]`、`outputs:["测试你好"]` |
| `{"prompt":"hi"}` | `outputs:["测试hi"]` |
| `{}` | `code:400102` |
| 非法 JSON | `code:400101` |

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| `找不到动态库` | 确认已 `cargo build --release`，路径指向 `target/release/` |
| `动态库未导出符号` | 用 `dumpbin /exports`（Windows）或 `nm -D` 确认 `post_chat` |
| `OSError: [WinError 193]` | Python 与 DLL 位数不一致，统一为 x64 |
| 返回 `-2` 或输出被截断 | 响应超过 64 KiB，缩短输出或分页 |
| `code != 0` | 按响应 `msg` 与错误码排查请求 |
| 文件被占用 | 停止正在调用该 DLL 的进程后重新构建 |

## 7. 清理

`target/`、`plugintest/libary/`、`plugintest/database/` 与日志都不入库；
切换机器时重新构建并布置依赖即可。
