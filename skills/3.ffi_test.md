# FFI 测试（Deno + dytes test）

本地不再使用 cyctron 暴露 HTTP 端点。测试分两步：

1. `dytes test` 搭建依赖与安装演练环境；
2. Deno 直接加载动态库调用 `post_chat`。

## 1. 用 dytes test 搭建环境

```bash
cd think_base_call
cargo build --release
dytes test .
```

`dytes test` 会：

- 校验 `dytes.json`（设计插件执行完整规则）；
- 在包目录创建 `.dytes/` 并自动加入 `.gitignore`；
- 下载 `dependencies-*` / `test-dependency` 声明的依赖到 `.dytes/env/`；
- 在 `.dytes/run-<pid>/` 演练安装布局后清理。

成功时最后输出：

```text
OK: 包结构检查通过
测试目录: .../think_base_call/.dytes
依赖目录: .../think_base_call/.dytes/env
演练目录: .../think_base_call/.dytes/run-<pid>/dytes-test-<时间戳>
```

需要保留演练目录时加 `--keep`。

> dytes 0.2.3 及更早版本仍把 `mcp.tools` 当文件名数组校验，会报
> `mcp 工具文件名合法`。需要包含 2026-11-16 校验修复的版本（`post_chat` 对象数组），
> 或先用本地构建的 dytes 二进制。

## 2. Deno 直连 FFI

`ts/ffi_test.ts` 用 `Deno.dlopen` 加载动态库，参数类型为 `["buffer", "buffer"]`，
返回 `i32`。

```bash
cd ts
deno task ffi --lib ../think_base_call/target/release/think_base_call.dll \
  --input '{"input":"你好"}'
```

等价于：

也可以从仓库根直接运行：

```bash
deno run --allow-ffi --allow-read ts/ffi_test.ts \
  --lib think_base_call/target/release/think_base_call.dll \
  --input '{"input":"你好"}'
```

Linux / macOS 把动态库换成 `libthink_base_call.so` / `libthink_base_call.dylib`。

预期输出：

```json
{
  "return": 0,
  "response": "{\"code\":0,\"data\":{\"outputs\":[\"测试你好\"],\"prompts\":[\"问候\"]},\"msg\":\"success\"}"
}
```

## 3. 参数

| 参数 | 说明 |
| --- | --- |
| `--lib` | 动态库路径，必填 |
| `--symbol` | 导出符号，默认 `post_chat` |
| `--input` | 请求 JSON，默认 `{}` |
| `--cwd` | 调用前切换的工作目录 |
| `--buffer` | 输出缓冲区字节数，默认 65536 |
| `--json` | 只输出响应 JSON |

需要读取 `info.db` 的库用 `--cwd` 指向包含 `database/info.db` 的目录：

```bash
cd ts
deno task ffi --lib <动态库> --cwd <测试根目录> --input '{"supplier":"deepseek","prompt":"你好"}'
```

## 4. 冒烟用例

`think_base_call`：

| 输入 | 期望 |
| --- | --- |
| `{"input":"你好"}` | `prompts:["问候"]`、`outputs:["测试你好"]` |
| `{"prompt":"hi"}` | `outputs:["测试hi"]` |
| `{}` | `code:400102` |
| 非法 JSON | `code:400101` |

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| `dytes test` 报 `mcp 工具文件名合法` | dytes 版本过旧，升级到包含对象数组校验的版本 |
| `找不到动态库` | 先 `cargo build --release`，确认 `--lib` 指向 `target/release/` |
| `Deno.dlopen` 报找不到符号 | 确认导出名为 `post_chat`；`--symbol` 与清单 `ffi_symbol` 一致 |
| `Invalid FFI pointer type` | 参数类型用 `buffer`，不要用 `pointer` |
| Windows 加载失败 | Deno 与 DLL 必须同为 x64 |
| 返回 `-2` / 输出截断 | 响应超过缓冲区，调大 `--buffer` |

## 6. 清理

- `.dytes/` 由 dytes test 自动创建并忽略，无需提交；
- `target/`、`deno.lock` 与运行日志不入库。
